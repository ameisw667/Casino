## 3. Anforderungen

- CLI-Nutzung über `npm run sentry:...`-Wrapper, die intern `node_modules/.bin/sentry-cli` aufrufen — kein globaler Install nötig.
- Interaktiver CLI-Login läuft über `sentry-cli login` (Browser-OAuth) mit einem **persönlichen** Token, nicht über `SENTRY_AUTH_TOKEN` aus `.env.local` (das ist der Build-Token und soll von der interaktiven Diagnose-Session getrennt bleiben).
- Jede CLI-Abfrage bleibt lesend: `info`, `issues list` — keine `resolve`/`mute`/`unresolve`, keine `releases`/`sourcemaps`.
- MCP-Verbindung ausschließlich read-only bzw. mit Schreibschutz-Bestätigung pro Aktion (`default_tools_approval_mode = "writes"` analog zum archivierten Pilot, falls im aktuellen Host konfigurierbar).
- MCP-Konfiguration bleibt lokal im jeweiligen Agenten-Host (nicht im Repository), analog zur bestehenden Regel aus dem archivierten Pilot.
- Kein Secret (`SENTRY_AUTH_TOKEN`, DSN, persönlicher CLI-Token) landet im Klartext in dieser Datei, im Terminal-Log oder im Git-Verlauf.
- Status in der Tabelle oben wird erst nach echtem Nachweis (nicht nach Versuch) von 🔴 auf 🟢 gesetzt.
