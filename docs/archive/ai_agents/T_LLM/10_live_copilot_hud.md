## 3 — Verifizierter Ist-Stand (2026-09-07, vor dieser Härtung)

`copilot-math.ts` (vor L1) berechnete Crash-Überlebenswahrscheinlichkeiten über `const prob = (0.99 / multiplier) * 100;` und Dice-Multiplikatoren über `Math.round((99 / winChance) * 100) / 100`. Beide Literale (`0.99`, `99`) kodierten implizit „1 % House Edge", identisch zur tatsächlich verwendeten Server-Formel in `provably-fair.ts` (`getCrashMultiplier`: `(1 - houseEdge) / (1 - result)`; Dice-Multiplikator-Kommentar: `(1 - config.dice.houseEdge) * 100 / winChance`), aber ohne jede strukturelle Kopplung an `DEFAULT_GAME_CONFIG.crash.houseEdge`/`DEFAULT_GAME_CONFIG.dice.houseEdge` (`game-config.ts:68,73`, beide `0.01`).

`src/app/admin/games/GamesPageClient.tsx` referenziert `houseEdge` — bestätigt, dass ein Admin diesen Wert über das Admin-Dashboard live ändern kann. Kein Client-Game-Component (`src/components/casino/games/**`, `src/app/games/**`) referenzierte `houseEdge` zum Zeitpunkt dieser Analyse — die tatsächlich konfigurierte, potenziell admin-überschriebene House-Edge war im gesamten Client-Bundle nirgends verfügbar, weshalb eine vollständige Live-Anbindung des HUDs an eine Admin-Änderung eine deutlich größere, mehrseitige Änderung wäre als der hier behobene Default-Wert-Duplizierungs-Fund.

**Verifizierter Ist-Stand (2026-09-07, vor L2):** `getCrashCurrentZone` (nach L1, vor L2) — alle vier Risiko-Zonen-Zweige:

```ts
return {
  action: 'HALTEN (GRÜNE ZONE)',
  winProbability: currentSurvival,   // bereits korrekt von houseEdge abgeleitet (L1)
  expectedValue: -0.01,              // weiterhin ein eigenständiges, ungekoppeltes Literal
  ...
};
```

Dasselbe Muster (`expectedValue: -0.01`) wiederholte sich identisch in allen vier `return`-Statements der Funktion (Zeilen 436, 452, 468, 483 vor L2) — `winProbability` in jedem dieser Objekte war bereits korrekt (via `currentSurvival`, das seinerseits `getCrashSurvivalProbability(currentMultiplier, houseEdge)` aufruft), `expectedValue` im selben Objekt aber nicht. Kein bestehender Test in `copilot-math.test.ts` prüfte `getCrashCurrentZone(...).expectedValue` — die vier vorhandenen Zonen-Tests (Zeilen 173-189) assertierten ausschließlich `riskLevel` und `badgeText`.

## 4 — Meilensteine

### L1 — Hardcodierte 1%-House-Edge-Annahme durch geteilte Config-Quelle ersetzen ✅ ausgeführt (2026-09-07)

- **Ziel:** Die in §2 #6/#7/#8 benannte strukturelle Drift-Gefahr schließen — ein einziger, im Projekt bereits existierender Config-Wert speist beide Formeln, statt zweier unabhängiger Zahlenliterale, die beim nächsten Refactor auseinanderlaufen könnten (derselbe Fundtyp wie der bereits in [`01_function_calling.md`](01_function_calling.md) behobene Rate-Limit-Fund).
- **Umsetzung:** `getCrashSurvivalProbability(multiplier, houseEdge = DEFAULT_GAME_CONFIG.crash.houseEdge)` und `getCrashCurrentZone(currentMultiplier, houseEdge = DEFAULT_GAME_CONFIG.crash.houseEdge)` ersetzen die feste `0.99` durch `(1 - houseEdge)` in der Formel; `getDiceOdds(target, isOver, houseEdge = DEFAULT_GAME_CONFIG.dice.houseEdge)` ersetzt `99` durch `(1 - houseEdge) * 100` und macht `expectedValue` sowie die „Hausvorteil"-Anzeigetexte (`reasoning`, `metrics`) dynamisch statt fest `-0.01`/`'1.0%'`. Da der Default-Parameterwert weiterhin exakt `0.01` ist (identisch zum vorherigen hardcodierten Verhalten), ist das Ergebnis für jeden bestehenden Aufrufer (`useGameCoPilot.ts`, alle 5 Spielseiten) byteidentisch — nur die Quelle des Werts hat sich geändert.
- **Neue Tests:** `copilot-math.test.ts` — „derives its default house edge from the shared game-config default..." (2×, Crash + Dice) beweist, dass der Default tatsächlich aus `DEFAULT_GAME_CONFIG` gelesen wird, nicht aus einer separaten Kopie; „recomputes ... for an explicitly passed house edge..." (2×, Crash + Dice) beweist, dass ein abweichender Wert die Formel korrekt neu berechnet (z. B. `getCrashSurvivalProbability(2.0, 0.02)` → `49.0` statt `49.5`).
- **Verifizierung (2026-09-07):** `npm run typecheck` 0 Fehler · gezielter Testlauf `copilot-math.test.ts` 17/17 grün (13 bestehende + 4 neue) · voller Testlauf `npm run test` grün (0 Fehlschläge; die Gesamtzahl schwankt zwischen Läufen durch parallele, unabhängige Arbeit im selben Repo — dasselbe bereits in Stufe F/R3 dokumentierte Muster, siehe `docs/archive/09_stufe_f_pgvector_admin.md` §5) · `npm run lint` 0 Fehler, keine neue Warnung in den geänderten Dateien · `npm run build` erfolgreich · `git status --short -- src/lib/casino/copilot-math.ts src/lib/casino/__tests__/copilot-math.test.ts` zeigt nur diese 2 beabsichtigten Dateien.

### L2 — `getCrashCurrentZone`s `expectedValue` an `houseEdge` koppeln ✅ ausgeführt (2026-09-07)

- **Ziel:** Die in §2 #11 / §3 (L2-Abschnitt) benannte Lücke schließen — jedes von `houseEdge` abgeleitete Feld in `getCrashCurrentZone` muss konsistent auf den Parameter reagieren, nicht nur `winProbability`.
- **Umsetzung:** Alle vier `expectedValue: -0.01`-Literale in `getCrashCurrentZone` (Safe/Balanced/High-Risk/Moon-Zone) wurden durch `expectedValue: -houseEdge` ersetzt — dieselbe Formel, die `getDiceOdds` bereits für sein eigenes `expectedValue`-Feld verwendet. Ein kurzer Kommentar direkt vor der Funktion dokumentiert den Fund für künftige Änderungen. Da der Default-Parameterwert weiterhin `0.01` ist, bleibt das Ergebnis für jeden bestehenden Aufrufer byteidentisch (`-houseEdge` mit `houseEdge = 0.01` ergibt exakt `-0.01`).
- **Neue Tests:** `copilot-math.test.ts` — „derives every risk zone's expectedValue from the shared house-edge default..." prüft alle vier Zonen gegen `-DEFAULT_GAME_CONFIG.crash.houseEdge`; „recomputes every risk zone's expectedValue for an explicitly passed house edge..." prüft alle vier Zonen mit einem abweichenden Wert (`0.03`).
- **Verifizierung (2026-09-07):** `npm run typecheck` 0 Fehler · gezielter Testlauf `copilot-math.test.ts` 19/19 grün (17 bestehende + 2 neue) · voller Testlauf `npm run test` 1665/1665 grün · `npm run lint` 0 Fehler (30 Warnungen gesamt, keine in den geänderten Dateien) · `npm run build` erfolgreich · `git status --short` zeigt nur `src/lib/casino/copilot-math.ts` (M) + `src/lib/casino/__tests__/copilot-math.test.ts` (M).
