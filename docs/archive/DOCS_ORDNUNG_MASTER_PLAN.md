### 2.3 Identifizierte Probleme (Konsolidierungs- & Optimierungshebel)

1. **Keine Trennung „lebendig" vs. „historisch/ausgeführt".** `architecture/` und `superpowers/` mischen beides. Ein vollständig abgehakter Plan (alle `[x]`) neben einer lebendigen Architekturdatei verwirrt das LLM darüber, was autoritativ/aktuell ist.

## 3 — Struktur-Optionen (Punkt 1: Ordner-Optimierung)

Vier Optionen, bewertet nach LLM-Nutzen, Aufwand, Link-Bruch-Risiko.

### Option A — Lifecycle-Triage (minimal)

Nur `docs/archive/` füllen; Ordnerstruktur bleibt. Lebendige Dateien bleiben in `architecture/`/Top-Level, alles Abgeschlossene/Historische wandert nach `archive/`. Keine Umbenennung bestehender Ordner, keine Neue.

- **Pro:** niedrigstes Link-Bruch-Risiko (nur verschobene Dateien brauchen Link-Fix), schnell.
- **Contra:** Namensinkonsistenz & Nummernkollision bleiben; kein Index.

### Option B — Single-Source + Index (konsolidierend)

`docs/README.md` als LLM-Einstieg; `architecture/` auf 2–3 lebendige Docs reduziert; `DESIGN_SYSTEM` als kanonische Quelle (CLAUDE.md verlinkt nur); `superpowers/`+`routes/` komplett nach `archive/`.

- **Pro:** stärkster LLM-Nutzen (klar autoritativ + Index), wenig Duplikate.
- **Contra:** höherer Aufwand; einige Link-Fixes nötig; `superpowers/`-Speccs haben ADR-Wert (Verlust, wenn nur archiviert).

### Option C — Nummerierte Lifecycle-Ordner (an Worldmap angelehnt)

`docs/01-status/` (ehem. status-reports), `docs/02-architecture/`, `docs/03-history/` (archive), `docs/04-decisions/` (ADRs), `docs/05-prototypes/`. Alles umnummeriert.

- **Pro:** konsistent mit Worldmap-Nummerierung; visuell selbsterklärend.
- **Contra:** **höchstes Link-Bruch-Risiko** (fast jeder Hub-Link bricht), hoher Aufwand, geringer Zusatznutzen gegenüber A/B — das LLM profitiert von einem Index mehr als von Ordnernamen.

### Option D — Pragmatic Triage + Index (Empfehlung) ✅

Kombination aus A + B ohne C's Umnummerierung:

- `docs/README.md` Index (LLM-Einstieg; pro Datei: Zweck · lebendig/archiv · Besitzer · last-updated).
- `docs/archive/` sammelt alle ausgeführten/historischen One-off-Pläne (routes, crash-visual, wallet-admin, meta-features, auth-history).

- Keine Ordner-Umbenennung, keine Neue außer `archive/`-Füllung.
- **Pro:** maximaler LLM-Nutzen (Index + klare Lebendig/Historisch-Trennung) bei **mittlerem** Link-Bruch-Risiko (nur verschobene/gelöschte Dateien → in M10 zentral fixt). **Contra:** etwas mehr Aufwand als A (Index), aber weniger als C.

### Empfehlung: **Option D.**

Begründung: Der größte LLM-Hebel ist der **Index** („welche Datei lese ich wann?") plus **Lebendig/Historisch-Trennung** — nicht die Ordnerbenennung.
