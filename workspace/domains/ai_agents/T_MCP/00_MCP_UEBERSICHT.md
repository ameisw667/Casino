### 7.1 — Was bereits vorhanden ist und was ein MCP zusätzlich bringt

Die sieben Kategorien aus Abschnitt 3 bleiben unverändert: Nur **Playwright** und **Context7** stehen derzeit lokal in [`.mcp.json`](../../../../.mcp.json); GitHub und Sentry sind nachgewiesene frühere Host-Piloten, Supabase, Vercel und DeepWiki sind geplante Piloten. Das Repository nutzt bereits Sentry, PostHog und Trigger.dev als normale Bausteine im Anwendungscode. Ein MCP ersetzt diese Bausteine nicht: Er gibt einem LLM einen begrenzten Arbeitszugang für Diagnose, Analyse oder Recherche.

**Entscheidungsregel:** Erst ein kleiner Read-only-Pilot mit klarer Frage und geprüftem Nachweis. Ein Server mit Schreibfunktionen darf nur dann weiter bewertet werden, wenn einzelne Lesetools eindeutig begrenzt werden können; sonst bleibt er ausgeschlossen.

### 7.5 — Die drei sinnvollsten nächsten Evaluationen

1. **GitHub-Security-Ausbau (E1):** Erstes Ziel ist ein präzises, rein lesendes Inventar bereits vorhandener Sicherheitswarnungen. So lernt Jan die Verbindung zwischen lokaler CI, GitHub-Befunden und echten Prioritäten.
2. **Chrome DevTools MCP (E2):** Ein lokaler, anonymisierter Browser-Pilot liefert sofort verwertbare Qualitätsdaten für eine visuell anspruchsvolle Next.js-Oberfläche, ohne ein externes Konto zu benötigen.
3. **Trigger.dev MCP (E4):** Der Dev-only-/Read-only-Pilot macht die bereits vorhandenen Hintergrundjobs nachvollziehbar und stärkt die Betriebsfähigkeit, ohne Jobs auszulösen oder auszurollen.

### 7.6 — Vorschlag für den Obsidian-Brain-Eintrag

Für jeden später freigegebenen Kandidaten genau eine kurze Notiz führen: **Ausgangsproblem → kleinster Read-only-Pilot → belegter Nutzen → Sicherheitsgrenze → Entscheidung**. Das hält nicht nur fest, welches Tool existiert, sondern welche Fähigkeit Jan daraus aufgebaut hat.

### 9.1 — Sinnvolle Lernreihenfolge

1. **Kern-Loop:** GitHub, Context7, Playwright, Chrome DevTools und Figma.
2. **Fullstack-Loop:** Supabase oder eine Alternative, Vercel, Sentry und Trigger.dev.
3. **Qualitaet:** Semgrep, danach genau eines aus Snyk, Datadog oder Grafana - nur wenn eine echte Luecke bleibt.
4. **Spezialisierung:** Erst dann Payments, Cloud, Datenplattform, Automatisierung oder KI-Suche passend zum Produkt.

**Merksatz fuer Obsidian:** Ein MCP ist kein Upgrade, weil es viele Tools hat. Es ist ein Upgrade, wenn es eine konkrete Entscheidung mit aktuellerem Kontext, weniger Fehlern oder besserer Beobachtung ermoeglicht - und seine Rechte dafuer klein genug bleiben.
