## 0 — Ausgangslage (verifiziert 2026-09-13)

- **Fund #3 (ARIA):** `src/components/casino/controls/BetInputGroup.tsx:132-138` — das `<input type="number">` für den Wetteinsatz trägt `aria-valuemin={minBet}` und `aria-valuemax={maxBet}`, aber **keine nativen** `min`/`max`-Attribute. `npm run lint` meldet `jsx-a11y/role-supports-aria-props`, weil die berechnete Rolle des Elements diese `aria-value*`-Attribute ohne die nativen HTML-Attribute nicht als gültig ansieht. Das ist kein Lint-Rauschen, sondern der korrekte Hinweis: für `<input type="number">` sollten `min`/`max` als **native** HTML-Attribute gesetzt werden — der Browser leitet daraus automatisch die richtige ARIA-Semantik ab (WAI-ARIA "erste Regel": kein ARIA verwenden, wo natives HTML dieselbe Semantik liefert). `BetInputGroup.tsx` wird von allen 6 Spielmodi verwendet — der Fix wirkt sofort repoweit.
- **Fund #6 (Live-Region):** `src/components/casino/games/roulette/RouletteHistoryBar.tsx` rendert die letzten 18 Gewinnzahlen rein visuell (farbige Badges), ohne jede `aria-live`-Region. Ein Screenreader-Nutzer erfährt das Rundenergebnis nicht automatisch. Das Muster `aria-live="polite"` mit visuell verstecktem Text ist im Repo bereits etabliert (7 bestehende Fundstellen, u. a. `ConsentBanner.tsx`, `NotificationCenter.tsx`, `GuideMessageList.tsx`) — hier wird dasselbe etablierte Muster übertragen, keine neue Technik eingeführt.
- **Testabdeckung heute:** `BetInputGroup.tsx` hat keine dedizierte Testdatei (`grep` auf `__tests__` liefert 0 Treffer). `RouletteHistoryBar.tsx` ebenfalls ungetestet.

**Abweichung vom Plan-Text (L3):** Der Plan nahm an, im Repo existiere bereits eine `.sr-only`-Utility-Klasse. Eine frische Prüfung (`grep -r "sr-only" src/`) vor der Implementierung ergab 0 Treffer — es gibt keine solche Klasse, und keine der 7 referenzierten bestehenden `aria-live`-Fundstellen versteckt ihren Text visuell (sie sitzen alle auf ohnehin sichtbaren Elementen). Da `RouletteHistoryBar.tsx` durchgehend Inline-Styles statt Tailwind-Klassen nutzt, wurde stattdessen ein lokales `VISUALLY_HIDDEN_STYLE`-Objekt (Standard-Clip-Technik: `position: absolute`, `width/height: 1px`, `clip: rect(0,0,0,0)`, `overflow: hidden`) ergänzt — funktional identisch zu `.sr-only`, aber konsistent mit der bestehenden Codier-Konvention dieser Datei.

**Kein Fan-out nötig:** Gesamtaufwand liegt deutlich unter der 45-Minuten-Schwelle aus `xx_sop/03_workflow_jan_planungsdateien.md` Kriterium 6 — beide Fixes sind klein, unabhängig genug, aber zu trivial für separate Parallelisierung.
