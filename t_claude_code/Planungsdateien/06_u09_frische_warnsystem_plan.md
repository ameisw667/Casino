### 2b — Warum kein Umsetzungshebel existiert (Plattform-Eigentum)

Der Mechanismus ist Plattform-Eigentum: Warnhinweis-Formulierung, Altersschwelle und Trigger-Logik liegen außerhalb des Repos (`C:\Users\hambu\.claude\`), sind dort weder im Code einsehbar noch vom Projekt aus änderbar. Ein klassischer Umsetzungshebel (Code/Config ändern, Schwelle justieren, Hinweistext verbessern) ist damit **strukturell unmöglich** — nicht nur schwer, sondern ausgeschlossen. Bewusster Doppelcharakter: Der Benefit ist gerade, dass das Projekt das System nicht ausbauen kann; derselbe Umstand schließt jede projektseitige Anpassung aus.

Was stattdessen geleistet wird — **Kompensation auf der Auswertungsseite**, nicht auf der Mechanismusseite:

### 2d — Beobachtungs-Checkliste (Inhalt von L1, wörtlich zu verankern)

**Pflicht-Fragen — je künftigem Memory-Read im Audit zu beantworten (Format: Ja / Nein / unbeobachtet):**

1. **Hinweis erschienen?** Kam vor dem Dateiinhalt ein Frische-System-Reminder? (Beobachtungsformat wie in der Basis-Datei Subsub 1: wörtliches Zitat + Alter)
2. **Alter korrekt?** Stimmt die genannte Altersangabe mit dem mtime/ls-Zeitstempel der Datei überein? (Beleg aus Subsub 1: `sql-delivery-as-file.md` mtime 2026-08-17 → 28 Tage, korrekt)
3. **Datum-vs.-Inhalt geprüft?** Wurde — unabhängig vom Hinweis — mindestens 1 Aussage der Datei gegen den Index bzw. gegen den aktuellen Code verifiziert und dabei auf einen Widerspruch Index-Zeile ↔ Dateiinhalt geprüft? (Regel R1/R2 aus §2a; hier entsteht der einzige Beleg dafür, ob der Hinweis Verifikationsverhalten auslöst — die heute unbelegte Komponente aus Subsub 8)

**Erweiterungs-Beobachtungspunkte — opportunistisch, wenn die Gelegenheit im Audit natürgemäß auftritt (keine künstliche Erzeugung, siehe §3):**

4. **Schwellen-Mitte:** Erscheint beim Read einer naturgemäß 2–9 Tage alten Datei ein Hinweis? → Grenzt den Schwellwert aus [2 … 10] weiter ein (Subsub 4).
5. **Index-Verhalten:** Bekommt `MEMORY.md` als Eingangsdatei bei höherem Alter einen Hinweis? (Beobachtungslücke aus Subsub 3: 1 Tag alt → kein Hinweis, Ursache Alter vs. Sonderrolle nicht trennbar)
6. **Subagent-/Tool-Abdeckung:** Erscheint der Hinweis bei Reads durch Subagenten bzw. bei Glob/Grep-Treffern im Memory-Ordner? (Beobachtungslücke aus Subsub 3)
7. **Reverse-Falsch-Frische:** Wurde eine Datei nur touchiert (mtime-Reset ohne inhaltliche Änderung) und der Hinweis damit zurückgesetzt, ohne dass das Wissen erneuert wurde? (unbeobachtete Richtung von G2, Subsub 6)
